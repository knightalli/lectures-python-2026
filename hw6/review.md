# Ревью кода модуля report.py

## Таблица найденных проблем

| Функция            | Что не так                                                                                                                                                                                      | Конкретный сценарий: входные данные и ошибка                                                                                                                                         | Серьезность                       |
| :----------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------- |
| `read_orders`      | Генератор возвращается из контекстного менеджера `with open`. Файл закрывается в момент выхода из функции, до начала чтения данных.                                                             | Вызов `next(read_orders('orders.txt'))` вызывает исключение `ValueError: I/O operation on closed file`.                                                                              | Падение                           |
| `totals_by_user`   | `groupby` группирует только строки, идущие подряд. Если заказы пользователя разделены заказами других клиентов, создаются разные группы, и словарь перезаписывает предыдущую сумму.             | На данных `[['anna', '100'], ['bob', '50'], ['anna', '700']]` вернет `{'anna': 700.0, 'bob': 50.0}` вместо `800.0` у anna.                                                           | Тихо неверный результат           |
| `has_large_orders` | Функция делает `bool(large)`, где `large` — объект-генератор. В Python любой генератор при приведении к `bool` всегда равен `True`, даже если он пустой.                                        | Для заказов `[['anna', '100']]` при пороге 1000 вернет `True`, хотя крупных заказов нет.                                                                                             | Тихо неверный результат           |
| `vip_over_limit`   | Использование стандартного `zip` молча отбрасывает элементы более длинного списка, если длины не совпадают. Если передать `None` в качестве отсутствующего лимита, операция `>` вызовет ошибку. | Если `vip_limits` короче `vip_users`, пользователи из конца списка вообще не проверяются. Если передать `None`, возникнет `TypeError: '>' not supported between float and NoneType`. | Тихо неверный результат / Падение |
| `last_orders`      | Использование `f.readlines()` считывает весь файл в оперативную память целиком в виде списка строк.                                                                                             | На файле размером несколько гигабайт программа займет всю память процесса и вызовет `MemoryError`.                                                                                   | Производительность / Память       |
| `build_report`     | Однократный итератор `orders` передается последовательно в `sum()`, затем в `totals_by_user()`. После `sum()` итератор полностью исчерпан.                                                      | `totals_by_user(orders)` получает пустой итератор, из-за чего в отчете поле `totals` всегда пустое: `{}`.                                                                            | Тихо неверный результат           |

## Решение по Кейт (для которой не указан лимит):
Если клиент указан в списке VIP, но лимит для него не задан, безопаснее всего считать, что лимит отсутствует (равен бесконечности `float('inf')`). Такой клиент не считается нарушившим лимит. В коде это реализуется через `itertools.zip_longest(..., fillvalue=float('inf'))`.
